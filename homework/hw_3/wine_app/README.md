# Винный помощник

Приложение для HW3. Используется уже обученный пайплайн `StandardScaler` →
`LogisticRegression(class_weight='balanced')`, порог по умолчанию — 0.5.
Класс 1 — хорошее вино с исходной оценкой не ниже 7. Внутри приложения обучения нет.

## Запуск

Проверяется с **Python 3.11.3**; для отдельного окружения используйте Python 3.11.
Откройте терминал в папке `wine_app`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Для Linux/macOS:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

В рабочем окружении курса из корня `ml hse`:

```powershell
.\.venv\Scripts\python.exe -m streamlit run ml_hse_2026/homework/hw_3/wine_app/app.py
```

## Что есть в приложении

- **Одно вино:** 12 полей, минимум, максимум и медиана из `test.csv`, переключатель цвета,
  вероятность класса 1 и решение. После первой оценки изменение порога сразу меняет решение.
- **Модельные метрики:** матрица ошибок, precision, recall, F1, ROC- и PR-кривые
  с точками текущего порога. PR-AUC считается как Average Precision.
- **Загрузка CSV:** проверка столбцов и чисел, оценка всех строк, скачивание результата.
  Поддерживаются запятая и точка с запятой как разделители; десятичный разделитель — точка.
- **Коэффициенты:** отсортированная диаграмма весов признаков после масштабирования.

Один ползунок в боковой панели задаёт порог для всех вкладок. Решение — класс 1,
если вероятность не меньше порога. В `config.json` сохранено значение по умолчанию.

## Формат CSV

Обязательные столбцы:

```text
fixed_acidity,volatile_acidity,citric_acid,residual_sugar,chlorides,free_sulfur_dioxide,total_sulfur_dioxide,density,pH,sulphates,alcohol,is_red
```

`is_red`: 0 — белое, 1 — красное. Остальные столбцы — числовые, без пропусков.
Порядок столбцов может быть любым. Лишние столбцы не используются моделью.
Пример CSV можно скачать во вкладке загрузки.

## Кэширование (задание 4.5)

`st.cache_resource` хранит один загруженный объект модели на сервере.
Модель нужна как общий ресурс, её не требуется копировать при каждом обращении.
Приложение не изменяет и не обучает этот объект.

`st.cache_data` используется для таблицы и массивов вероятностей: это данные,
пользователь получает свою копию результата. Аргумент `_model` исключён из хеширования;
вероятности кэшируются по таблице признаков. В приложении используется одна модель.
Порог не является аргументом `test_proba`, поэтому движение ползунка меняет только
метки, метрики и точки на графиках, а `predict_proba` на тесте повторно не вызывается.
Для загруженного CSV вероятности тоже кэшируются.

Если вызвать `joblib.load` без декоратора, модель будет читаться с диска при каждом
перезапуске скрипта, в том числе при движении ползунка. Все файлы загружаются относительно
`Path(__file__).parent`, поэтому запуск не зависит от текущей папки терминала.
